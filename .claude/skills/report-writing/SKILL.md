# report-writing

## 목적
작업/검증/요청 산출물의 양식을 표준화한다.

## 사용 시점
AGENT가 작업 완료, QA 검증 완료, 또는 코드/AGENT 변경 요청을 만들 때.

## 적용 대상
`docs/reports/`, `qa/reports/`, `qa/change-requests/`. 파일명: `YYYY-MM-DD-loopNN-<요약>.md`

## 절차
1. 알맞은 양식을 고른다(작업 보고서 / 변경 요청서).
2. 사실에 기반해 채운다(추측 금지).
3. 해당 디렉토리에 저장한다.
4. 후속 단계(QA 또는 승인)를 명시한다.

## AGENT 작업 보고서 양식
```
# AGENT 작업 보고서
## 1. 작업 AGENT
## 2. 작업 일시
## 3. 작업 목표
## 4. 수정한 파일
## 5. 생성한 파일
## 6. 주요 작업 내용
## 7. 기술적 판단 근거
## 8. 다른 AGENT 영역 영향 여부 (있음/없음, 변경 요청 필요 여부)
## 9. 남은 이슈
## 10. QA 요청 사항
## 11. 다음 Loop 제안
```

## 코드 수정 승인 요청서 양식 (qa/change-requests/)
```
# 코드 수정 승인 요청서
## 1. 수정 필요 여부 (필요/불필요)
## 2. 문제 요약
## 3. 영향 범위
## 4. 수정 대상 파일
## 5. 수정 사유
## 6. 수정 방향
## 7. 예상 변경 내용 (추가/변경/삭제)
## 8. 위험도 (LOW/MEDIUM/HIGH)
## 9. 수정하지 않을 경우 문제
## 10. 승인 요청 (승인/보류/수정 방향 변경 요청)
```

## AGENT 변경 요청서 양식 (qa/change-requests/)
```
# AGENT 변경 요청서
## 요청 대상 AGENT
## 요청 사유
## 관련 파일
## 요청 내용
## 영향 범위
## 우선순위 (HIGH/MEDIUM/LOW)
## 직접 수정하지 않은 이유
```

## 체크리스트
- [ ] 올바른 양식·디렉토리
- [ ] 사실 기반(파일·라인 명시)
- [ ] 후속 단계 명시

## 금지 사항
- 보고서 없이 다음 Loop 진행
- 추측을 사실처럼 기재

## 출력 형식
위 Markdown 양식 그대로.
