# loop-coding

## 목적
승인 기반 Bounded Loop Coding 절차를 일관되게 진행하기 위함. 무단 코드 수정과 검증 누락을
방지한다.

## 사용 시점
모든 신규 작업/수정 작업 시작 시. 메인 Claude(loop-orchestrator)가 가장 먼저 호출한다.

## 적용 대상
백엔드(`05-02.hanadream`) + 프론트(`05-06.hanadream_web_new`) 전체 작업.

## 절차
1. 작업 목표를 작은 단위로 정의한다.
2. 담당 AGENT를 선택한다(소유 영역 기준).
3. 관련 Skill을 확인한다.
4. 아래 "다음 Loop 작업 계획"을 출력한다.
5. 사용자 승인 필요 여부를 판단한다.
6. 승인 불필요한 문서/보고서/검증 작업을 수행한다.
7. 코드 수정이 필요하면 `approval-gate` Skill로 승인 요청서를 작성한다.
8. 사용자 승인 후 담당 AGENT가 자기 영역만 수정한다.
9. 작업 보고서를 작성한다(`report-writing`).
10. qa-code-reviewer가 검증하고 QA 보고서를 작성한다(`qa-code-review`).
11. PASS/WARNING/FAIL을 판단한다.
12. PASS → 다음 Loop / WARNING → 위험도 기록 후 사용자 판단 / FAIL → 승인 대기.

## 다음 Loop 작업 계획 (출력 양식)
```
# 다음 Loop 작업 계획
## 1. 작업 목표
## 2. 담당 AGENT
## 3. 관련 Skill
## 4. 수정 예상 파일
## 5. 사용자 승인 필요 여부 (필요/불필요)
## 6. 승인 요청
```

## Loop 종료 조건
- QA PASS
- QA WARNING(위험도 + 후속 개선 항목 기록)
- 사용자 중단 지시
- 동일 문제 3회 이상 반복 → 임의 수정 중단, 원인 분석 보고서 작성

## 체크리스트
- [ ] 작업 목표가 작은 단위인가
- [ ] 담당 AGENT 소유 영역이 명확한가
- [ ] 코드 수정 전 승인을 받았는가
- [ ] 작업 보고서를 남겼는가
- [ ] QA 검증을 거쳤는가

## 금지 사항
- 승인 없이 코드/설정/의존성/빌드 파일 수정
- QA 없이 다음 Loop 진행
- 보고서 없이 다음 Loop 진행
- AGENT 소유 영역 침범

## 출력 형식
"다음 Loop 작업 계획" → (승인 후) 작업 → 작업 보고서 → QA 보고서 → 판단.
